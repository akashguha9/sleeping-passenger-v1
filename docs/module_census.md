# `scripts/` Module Dead-Weight Census

A static, read-only classification of every top-level module in `scripts/`
into one of four reachability tiers, plus the minimum tooling to keep the
active runtime path from silently growing.

- **Generated by:** `tools/module_census.py` (import-safe, pure AST — imports
  no repo module). Regenerate with `python tools/module_census.py --json`.
- **Branch:** `claude/tender-pasteur-m4Bxd`
- **Population:** 322 top-level `scripts/*.py` modules.
- **Method:** import-BFS over `ast`-parsed import statements, following both
  `scripts.foo` and bare-`foo` fallback forms and descending into
  subpackages; only top-level `scripts/*.py` modules are classified.

> **⚠️ Correction vs the first census.** Two accuracy bugs in the generator
> were fixed and the numbers below supersede the earlier snapshot:
> 1. **BOM-tolerant read** — 36 `scripts/*.py` files carry a UTF-8 BOM; the
>    generator previously failed to AST-parse them (read as `utf-8`, not
>    `utf-8-sig`) and silently dropped their import edges.
> 2. **`from scripts import X` detection** — the test-reference scan missed the
>    very common `from scripts import foo` form, so many test-exercised modules
>    were mislabelled ORPHAN.
>
> The first census reported **145 ORPHAN**; the corrected figure is **69**. The
> difference was almost entirely modules that *are* exercised by tests via
> `from scripts import …`. No modules were added or deleted to achieve this —
> only the measurement was made honest.

## Tiers

| Tier | Meaning |
|---|---|
| **ACTIVE** | reachable by import-BFS from `run_diagnostics_pipeline.py` |
| **API_REACHED** | reachable from `api_server.py` but **not** from the orchestrator |
| **TEST_ONLY** | not reachable from either entrypoint, but imported by ≥1 file under `tests/` |
| **ORPHAN** | reachable from no entrypoint and no test (in **this branch**) |

## 6. "Do NOT delete without" checklist

Before removing **any** ORPHAN module, complete every step and record evidence.
A clean result here is necessary, not sufficient — when in doubt, keep it.

1. **Cross-branch grep.** `git fetch --all`, then
   `git grep -n "<module_stem>" $(git for-each-ref --format='%(refname)' refs/remotes)`.
2. **CI / build references.** Grep `.github/workflows/*.yml`,
   `Makefile`, `Dockerfile*`, `docker-compose.yml`.
3. **Dynamic imports.** Grep for `importlib`, `__import__(`, `import_module(`,
   and the bare string `"<module_stem>"` / `"scripts.<module_stem>"`.
4. **Config-file references by name.** Grep `config/`, `configs/`, `*.json`,
   `*.yaml`/`*.yml`, `*.toml`, `.env*`.
5. **Entry-point / `__main__` usage.** Confirm no operator/docs-referenced CLI.
6. **Re-run census + full suite** after staging removal; confirm tiers shift
   only as expected and `pytest` stays green.

Only with all six clean (and a human reviewer's sign-off) is removal justified.
