# `scripts/` Module Dead-Weight Census

A static, read-only classification of every top-level module in `scripts/`
into one of four reachability tiers, plus the minimum tooling to keep the
active runtime path from silently growing.

- **Generated by:** `tools/module_census.py` (import-safe, pure AST — imports
  no repo module). Regenerate with `python tools/module_census.py --json`.
- **Branch:** `claude/tender-pasteur-m4Bxd`
- **Population:** 320 top-level `scripts/*.py` modules.
- **Method:** import-BFS over `ast`-parsed import statements, following both
  `scripts.foo` and bare-`foo` fallback forms and descending into
  subpackages; only top-level `scripts/*.py` modules are classified.
- **Baseline at generation:** `5613 passed`; governance `DO_NOT_DEPLOY`,
  `can_deploy_capital=false`, `policy_state=RESTRICTED`.

## Tiers

| Tier | Meaning |
|---|---|
| **ACTIVE** | reachable by import-BFS from `run_diagnostics_pipeline.py` |
| **API_REACHED** | reachable from `api_server.py` but **not** from the orchestrator |
| **TEST_ONLY** | not reachable from either entrypoint, but imported by ≥1 file under `tests/` |
| **ORPHAN** | reachable from no entrypoint and no test (in **this branch**) |

> **Precedence:** a module reachable from both entrypoints is counted ACTIVE.
> API_REACHED excludes anything already ACTIVE.

## 7. "Do NOT delete without" checklist

Before removing **any** ORPHAN module, complete every step and record the
evidence. A clean result here is necessary, not sufficient — when in doubt,
keep it.

1. **Cross-branch grep.** `git fetch --all`, then
   `git grep -n "<module_stem>" $(git for-each-ref --format='%(refname)' refs/remotes)`
   — confirm no other branch imports or names it. Parallel-branch work
   (Kalshi/Busquets/Kante/cockpit/compliance) is the primary risk.
2. **CI workflow references.** Grep `.github/workflows/*.yml` and any
   `Makefile`/`Dockerfile*`/`docker-compose.yml` for the module name and its
   file path — orphan CLIs are frequently invoked by CI/release gates, not
   imports.
3. **Dynamic imports.** Grep the whole repo for `importlib`,
   `__import__(`, `import_module(`, and the bare string `"<module_stem>"` /
   `"scripts.<module_stem>"` — dynamic/string-keyed loading is invisible to
   the static BFS that produced this census.
4. **Config-file references by name.** Grep `config/`, `configs/`, `*.json`,
   `*.yaml`/`*.yml`, `*.toml`, and `.env*` for the module/file name —
   registries and feature flags often reference modules as strings.
5. **Entry-point / `__main__` usage.** Confirm the module has no
   `if __name__ == "__main__"` CLI that operators or docs (`README.md`,
   `DEMO.md`, `DEPLOYMENT.md`, `TESTING.md`) tell users to run directly.
6. **Re-run the census + full suite after staging the removal** and confirm
   tier counts shift only as expected and `pytest` stays green.

Only with all six clean (and a human reviewer's sign-off) is removal of an
ORPHAN module justified. This document authorizes none.
