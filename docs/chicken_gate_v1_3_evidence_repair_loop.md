# Chicken Gate v1.3 — Evidence Repair Loop

**ADVISORY-ONLY.** Nothing here executes, recommends sizing, or touches a
broker. The repair loop is an evidence-prioritization tool: it never
changes the live gate — only real evidence supplied via overrides changes
a later run.

## What changed from v1.2

v1.2 answered *"why blocked?"*. v1.3 answers *"what would I need to prove
to unblock it?"* — and audits the five-model synthesized output through
the same gate as the raw candidate.

New module: `scripts/chicken_gate_repair_engine.py`. Extended:
`scripts/chicken_gate_daily_bridge.py`, `scripts/daily_synthesis_pipeline.py`.

## Five-model roundtrip

The five-model synthesis runs outside Python
(`scripts/run_five_model_synthesis.ps1` → writes
`moltbook/five_model_synthesis_report_<run_date>.txt`, and the lanes work
writes `runtime/five_model_synthesis/<date>/final_synthesis.md`). The
bridge loads the report **strictly for the current run_date** (no stale
reuse), extracts each candidate's section (±2 lines around every mention),
and runs chicken-gate **pass #2** on the synthesized language — so the
gambler guard, label math, and every haircut audit what the models *said*,
not just the raw candidate. Structured outputs can also be passed via
`five_model_outputs={ticker: {...}}`.

Gate integration (mandatory min-rank, three-way):

    G_final = rank_to_gate(min(rank(G_existing),
                               rank(G_chicken_candidate),
                               rank(G_chicken_synth)))     # when synth exists

    S_integrated = min(available numeric scores)

If the report never mentions the ticker (or no report exists for the run
date): the row gets `INSUFFICIENT_EVIDENCE_FIVE_MODEL_SYNTHESIS`, and a
candidate otherwise reaching BUY_ALLOWED is capped at BUY_LIMITED
(`FIVE_MODEL_SYNTHESIS_NOT_AUDITED`). Disclosed, never silent, never a
hard block by absence alone.

## Evidence Repair Plan format

Per row, `EVIDENCE_REPAIR_PLAN` is a list of items:

    {
      "missing_or_weak_field": "LOAD_BEARING_NODE",
      "current_status": "MISSING | WEAK | SELF_REPORTED | HARD_BLOCKED | CAPPED",
      "affected_score": "LOAD_BEARING_NODE_SCORE",
      "affected_gate_rule": "missing/unproven load-bearing node caps at BUY_LIMITED",
      "required_evidence": "...",
      "expected_data_type": "...",
      "minimum_confidence_to_unlock": 0.7,
      "operator_override_field": "load_bearing_node / ...",
      "max_gate_if_fixed": "...",
      "repairable": true,
      "reason": "...",
      "repair_key": "LOAD_BEARING_NODE"
    }

Detected items: load-bearing node, net edge (missing or non-positive), IAP
evidence slots, first-signal date, self-reported component confidences,
channel verification, holdings, five-model synthesis, gambler's fallacy
(guarded), and the three **non-repairable** hard blocks (`SPOILAGE_RISK`,
`FRESHNESS_SPOILED`, `PROCESS_INTEGRITY_BELOW_3`) which are marked
`repairable: false` with the reason no override may touch them.

## Unlock simulation math

    if any non-repairable hard block: simulated_gate = BUY_BLOCKED
    else:
        repaired = thesis with threshold values filled for MISSING
                   repairable evidence only (present values NEVER replaced)
        r_simulated = min(rank(existing_gate), rank(gate(repaired)))

Threshold fills: node score 7.0 @ conf 0.7; edge 0.60/0.50/0.02; IAP slots
at moderate values; confidences 0.7. A real non-positive net edge stays
blocked in simulation — simulation completes the picture, never repaints it.

Repair priority (per item j, one gate evaluation each):

    Priority_j = (gate_lift_j * 2 + score_lift_j / 10)
                 * repairability_j * (1 - effort_j)      # >= 0, top 3 kept

## Override template

`runtime/chicken_gate_thesis_overrides.template.json` — autogenerated on
`--write` from actual repair plans, one block per unlockable (repairable,
sub-BUY_ALLOWED) ticker: every override field nulled for filling,
`_priority_repairs` naming the top fixes, `do_not_override_if` warnings,
and `_non_repairable_do_not_touch` when hard blocks exist. Copy filled
entries into `runtime/chicken_gate_thesis_overrides.json` for the next run.

## Payload health

    PayloadHealthScore = 10 * (0.25*price_availability + 0.25*cqs_nonzero
                             + 0.20*probability_availability
                             + 0.15*thesis_availability
                             + 0.15*source_channel_availability)

Score < 5 adds: *"DAILY_PAYLOAD_DEGRADED: Do not interpret mass
BUY_BLOCKED as market-wide bearishness; interpret as insufficient evidence
quality."* Observed on the current repo payload: **3.0/10, degraded** —
today's mass block is a data-quality fact, not a market view.

## Honesty metadata

`chicken_gate_repair_engine.THEORETICAL_COMPONENTS` is an empty tuple —
tests assert it stays empty, so no scoreboard segment may claim unshipped
capability. Remaining constraints are external data, listed in
`EXTERNAL_DATA_CONSTRAINTS` (live provider quality; closed-outcome corpus
size for weight calibration).
